## 楼中楼图片支持点击放大

- 文件：`src/views/post/post.html`
- 背景：楼中楼评论内容由 `src/api/index.ts` 的 `pbContentHtml` 生成 HTML 字符串（图片带 `class="comment-img"`），前端用 `v-html` 渲染，因此不能直接绑定 Vue 的 `@click`。
- 方案：在评论内容容器上做事件委托 —— `<div v-html="comment.content" @click="onClickCommentImage">`，方法内判断 `event.target.classList.contains('comment-img')`，命中则复用主楼已有的 `onClickImage(src)` 设置 `previewSrc` 打开大图遮罩。
- 同时给 `.post-item .comment-img` 补了 `cursor: pointer`（与主楼 `.common-img` 一致，作为可点击提示）。
- 未改后端，未加 `title="点击进入大图模式"` 提示（如需与主楼完全一致，可在 `pbContentHtml` 的 img 字符串里补该属性）。

## 楼中楼图片透明度对齐主楼

- 文件：`src/views/post/post.html`
- 原 `.post-item .comment-img` 里有 `opacity: 1;`，覆盖了父级 `.post-item img { opacity: 0.3 }`，导致楼中楼图片不透明。
- 已删除该行，`.comment-img` 现在继承 0.3，与主楼 `.common-img`、表情一致；尺寸规则（height/width auto、max-width 200px）未动。
- 结论备忘：`.post-item img` 是统一透明度入口（0.3），任何 `.xxx-img` 类若写 opacity 都会破坏一致性。

## 屏蔽直播间推广帖（营销帖）

- 文件：`src/api/index.ts`
- 探测结论（实测，重要）：
  - `thread.field 59`（is_ad）在真实数据里几乎恒为 0。扫了高达模型/手机吧/李毅吧/王者荣耀吧/和平精英吧/原神吧/孙笑川吧/steam吧 约 200 条 thread，无一命中，说明现有 `is_ad` 过滤实际近乎无效。
  - 真正的 banner 广告在 data 层独立字段（李毅吧 `#100`，如 "240天SVIP免费送" + bcebos 图片），不进 thread_list，本来就看不见。
  - `thread.field 234` 是 map<string,string> 扩展包，子消息 key(1)/value(2)，出现过 `fid`/`tid`/`card_type=normal`/`head_tag`；但只有部分吧下发，且没见到非 normal 取值。
  - `thread_list` 为空时走 `pbThreadTitles` 兜底（用 `forum.field 20` 的 tid 列表逐条取标题），该路径原本没有任何过滤，现已一并加上。
  - 直播间推广帖无稳定字段标记（每次投放内容不同），最终只能按标题特征兜底。
- 实现：新增 `AD_TITLE_KEYWORDS` + `isAdThread(title)`，规则为「标题含 ≥2 个 `·`/`•`/`・` 分隔」或「命中营销词表」。
  - 词表刻意收窄为 `暴富厅/福利厅/带你飞/等你进来/点击领取/红包群`；早期试过 `进群/加微信/私聊我` 会误杀「新人进群求带」等正常帖，已剔除。
- 应用点：`getThreadList` 的 thread_list 循环内 + `pbThreadTitles` 兜底返回值 filter。
- 未覆盖：帖子内部楼层里的广告、视频帖识别（`pbContent` 只认图片 type 3/20、表情 2/11，视频碎片会被当文本，正文可能残缺）。

## 广告消失的根因（git 溯源，重要结论）

- 今天 15:41 的 `f3ae66c feat: 迁移贴吧移动端接口并支持楼中楼分页` 重写 `src/api/index.ts`（703 行变更），旧版三道过滤全部丢失：
  | 防线 | 旧版（网页 DOM） | 新版（protobuf） |
  |---|---|---|
  | 视频贴 | `if(!hasVideo)` 判 `.threadlist_video`（`126759b`） | 无 |
  | 老式广告楼 | `attr('ad-dom-img') === 'true'` | 无 |
  | 新型广告楼 | `attr('data-field') === '{}'`（`abcf7d0`，2024-12 专门发版） | 无 |
- 机制：旧版按 `.j_thread_list` / `.l_post` 取节点，网页端广告是独立 DOM（class 不同），遍历时天然被跳过；新版是扁平数组，推广帖与正常帖地位相同，必须显式过滤。
- 已补（内容层）：`getPostList` 中判断 `!pid || !postDate || !authorId` 即跳过，等价旧版 `data-field === '{}'`。实测 3 个帖共 52 层正常楼层，误杀 0。
- 实测经验：很多正常帖 `author(23)` 字段为空，靠 `user_list`（field 13）兜底，所以不能用「author 为空」判断广告，必须用 `author_id(19)`。
- 尚未补：视频贴（protobuf 里无等价 CSS class，需探测 thread 的 video 标记字段）。
- 注意：用户在列表里刷到的直播间推广帖元数据完整（有作者、时间、正文），上述内容层过滤拦不住，只能靠标题特征。
